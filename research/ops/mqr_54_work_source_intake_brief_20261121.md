## 실행 규칙

1. **먼저 정본 대조:** 위 GitHub 미보유 원장 최신판, MQR 5.4 README, Drive 공통 보관 폴더에서 제목·저자·연도·판본을 확인한다. 대규모 Drive 10/11 폴더는 첫 화면 최대 100개만 보일 수 있으므로 그 화면을 전수 목록이라고 선언하지 않는다. 이미 보유한 동일 판본은 다시 받지 않는다.
2. **Work의 웹 탐색과 컴퓨터 사용:** 공식 학술기관, 저자 사이트, 출판사 OA, 국립도서관, Internet Archive/Wikimedia Commons처럼 적법한 원문 접근 경로를 우선한다. 저작권·접근권·재사용 허락이 확인되지 않으면 다운로드하지 않는다. paywall, CAPTCHA, 계정·인증, DRM, robots, 차단회피를 우회하지 말고 HOLD와 근거 링크만 남긴다. 저자에게 이메일 발송·유료구매·계정 생성은 직접 수행하지 않는다(초안 또는 승인 요청만).
3. **실제 수집:** 내용 확인과 합법적 다운로드가 가능한 파일은 원본 바이트를 변형하지 않고 저장한다. 파일 메타데이터, 페이지 수, 첫/마지막 페이지, 표제·저자·출판 연도·판본, SHA-256을 기록한다. 이름 형식은 실제 commons의 기존 자료와 비교해 정한다. 처음에는 정본 `00_INTAKE`로 입고, 확인이 확실하면 논문→10_PAPERS, 책·보고서·사료→11_SOURCES, 기타 참고자료→20_NON_PAPER_SOURCES로 **동일 Drive 파일 ID를 유지해 이동**한다. 판본 불명·깨진 파일·중복 위험이 있으면 00에 격리하고 임의 덮어쓰기/삭제하지 않는다.
4. **로컬 PC와 Work:** Work/데스크톱 연결에서 로컬 폴더 접근이 실제 허용·확인되면 그 경로를 사용할 수 있다. 클라우드 브라우저가 로컬 `C:\` 드라이브에 자동 접근한다고 가정하지 않는다. 로컬 경로가 확인되지 않으면 **연결된 Drive**를 정본으로 사용하고 실패를 기록한다. 비밀번호·보안토큰을 파일명, 표, 로그에 쓰지 않는다.
5. **중복과 보존:** 바이트 중복(SHA)와 내용 판본 중복(같은 본문 다른 스캔)을 구분. 원래 존재하던 파일을 삭제·이름 변경하지 않는다. 최초 파일 ID·새 부모 ID·URL·해시·원래 위치를 남긴다. 공개 저장소나 GitHub에 저작권 있는 책 전체나 MQR 대화 원문을 업로드하지 않는다.
6. **Chat 모드와 역할 분리:** Work는 문헌 파일의 수집/검증/분류와 인계 목록을 담당한다. 연구 질문·논증·과학사 해석·코드 개발 및 `WhoSia` 명의 GitHub 커밋은 별도 Chat 모드가 담당한다. `github-actions[bot]` 커밋을 만들지 않는다. 본 업무의 실행을 MQR 5.5 승격이나 문헌 원장의 17건 종결로 해석하지 않는다.

## 결과물 계약

**반드시 항목 A1~A4 및 5~17을 각각 1행으로 다룬 17행 상태표**를 제공한다. 각 행에 `그룹/정확한 판본/이미 보유한 것/공식 출처 URL/공개 파일 직접 URL·권리상태/다운로드 여부/저장한 Drive 폴더와 file ID/파일명/쪽수/SHA256/판본·본문 검증/HOLD 이유와 다음 합법적 확보 경로`를 기록한다. 자료를 실제로 다운로드하지 못했으면 **파일 ID·SHA·쪽수 등을 만들어내지 않는다.** 논문·책 단위로 신규 확보에 성공한 건수와 기존 보유 판본의 재발견을 분리한다. A3/A4는 끝까지 미수행 실험으로 보존한다.

보고서 마지막은 `새로 실제 입고한 항목`, `기보유 확인 항목`, `접근권·원고 원판 보류`, `연구자 데이터 요청 초안`, `Chat 모드로 넘길 가장 가치 높은 새 문헌 3개`로 요약한다. 핵심 파일·링크의 성공적인 열람 확인을 한 뒤 실행을 끝낸다. 사용자 승인이 필요한 단계는 수행하지 말고 정확히 무엇에 대한 승인이 필요한지 적는다.
