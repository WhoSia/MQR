## Explanandum lock

Given two or more constitution versions:

```text
C_t  with burden ontology B_t
C_t+1 with burden ontology B_t+1
```

under what conditions may obligations, debts and coverage claims be compared or transported when:

- an old burden is refined into several new burdens;
- several old burdens are merged;
- the same label changes meaning;
- different labels become extensionally equivalent under a declared challenge set;
- old and new burdens only partially overlap;
- a burden disappears without an explicit equivalence/withdrawal proof;
- direct and composed ontology translations disagree;
- competing constitutions impose incompatible exploration obligations;
- no mapping can certify that every future scientifically relevant burden has been represented?

The court must distinguish:

```text
SAME LABEL != SAME BURDEN
DIFFERENT LABEL != DIFFERENT BURDEN
SUCCESSOR ONTOLOGY != AUTOMATIC DEBT DISCHARGE
CROSS-VERSION MAPPING != WORLD-IDENTITY
COMPARABLE != COMMENSURABLE
ARBITRATED != TRUE
```

## Candidate canonical objects

### 1. Burden-Ontology Revision Receipt (BORR)

A BORR records:

- source constitution and ontology version;
- target constitution and ontology version;
- burden declarations on both sides;
- typed source->target mapping edges;
- mapping provenance;
- debt-bearing source burdens;
- target obligation coverage;
- explicit withdrawals;
- conflict set;
- path provenance;
- direct-vs-composed translation status;
- open-world residue.

BORR is a transport receipt, not a burden-identity oracle.

### 2. Burden Transport Relation (BTR)

Each declared mapping is typed:

```text
EXACT
REFINE
MERGE
OVERLAP
DISJOINT
UNMAPPED
```

Interpretation is constitutional and version-relative.

- EXACT: the receipt asserts full declared burden preservation.
- REFINE: one source burden is represented by the union of multiple target burdens.
- MERGE: multiple source burdens map into one target burden.
- OVERLAP: partial preservation only; no full debt discharge.
- DISJOINT: explicit nonidentity.
- UNMAPPED: translation unavailable.

None establishes metaphysical/world identity.

### 3. Burden-Identity Witness (BIW)

An EXACT claim must have an explicit witness basis, e.g. declared challenge/coverage equivalence.

The checker may audit presence and consistency of the witness. It may not infer world identity merely from the label EXACT.

### 4. Debt-Transport Ledger (DTL)

Debt remains indexed to source burden ancestry until a qualifying transport condition is satisfied.

Default:

```text
SOURCE DEBT
-> EXACT target coverage
or
-> REFINE full-union target coverage
or
-> MERGE target coverage with source provenance retained
or
-> explicit withdrawal
otherwise
-> UNRESOLVED TRANSPORT DEBT
```

### 5. Revision Loss Vector (RLV)

Loss is typed rather than scalar:

- unmapped source burden;
- partial-overlap residue;
- merge provenance collapse;
- target-only novel burden;
- debt continuity gap;
- conflict introduced;
- path inconsistency.

No default weighted sum is authorized.

### 6. Cross-Constitution Comparability Envelope (CCE)

Two constitutions are comparable only on mapped declared burden coordinates.

```text
COMPARABILITY DOMAIN = MAPPED SUBSPACE
NOT = ENTIRE SCIENTIFIC AGENDA
```

### 7. Obligation Conflict Receipt (OCR)

Conflict is localized when translated obligations cannot jointly satisfy their declared statuses under the target constitution.

Candidate states:

```text
NO_CONFLICT
COMPATIBLE_REFINEMENT
MERGE_COLLISION
MANDATE_CONFLICT
WITHDRAWAL_CONFLICT
UNMAPPED_CONFLICT
ARBITRATION_REQUIRED
```

The court may expose conflicts and admissible resolution conditions. It does not select a scientifically true winner without an explicit higher-order authority rule.

### 8. Revision Diamond Receipt (RDR)

For ontologies A, B, C:

```text
A -> B -> C
A ------> C
```

compare direct and composed burden transport.

If they disagree on preserved debt/coverage:

```text
REVISION DIAMOND NONCOMMUTES
-> CROSS-VERSION AUTHORITY REOPENED
```

Path agreement is not world truth; disagreement is a strong reopening signal.

## Core countermodel 1 — same label, different burden

Version V1:
```text
burden A = challenge {q1}
```

Version V2:
```text
burden A = challenge {q1,q2}
```

The label is unchanged but the declared burden differs.

Therefore:

```text
LABEL PERSISTENCE != BURDEN IDENTITY
```

## Core countermodel 2 — different label, declared exact equivalence

Version V1:
```text
A = {q1,q2}
```

Version V2:
```text
Z = {q1,q2}
```

A declared challenge-equivalence witness may support local EXACT transport despite label change.

Therefore:

```text
LABEL CHANGE != BURDEN NONIDENTITY
```

## Core countermodel 3 — refinement debt

Source debt:

```text
A = {q1,q2}
DEBT(A)
```

Target ontology:

```text
A1 = {q1}
A2 = {q2}
A --REFINE--> {A1,A2}
```

Debt is transportable only if target coverage preserves the full declared refinement union.

Funding/clearing A1 alone cannot retire DEBT(A).

## Core countermodel 4 — merge laundering

Source:

```text
DEBT(A)
CLEAR(B)
A+B --MERGE--> M
```

If M is marked CLEAR without retaining source-provenance debt:

```text
MERGE DEBT LAUNDERING = DETECTED
```

A merge may compress representation, not erase source debt.

## Core countermodel 5 — noncommuting revision diamond

Construct:

```text
A --REFINE--> {B1,B2}
B1+B2 --MERGE--> C

but direct
A --OVERLAP--> C
```

Then composed transport may report full preservation while direct adjudication reports only overlap.

Target:

```text
LOCAL MAPPINGS PASS
!=
PATH-INDEPENDENT BURDEN TRANSPORT
```

## Frozen attacks

### Attack 1 — Same-Label Semantic Drift
Keep burden ID fixed while declared challenge/coverage content changes.

### Attack 2 — Different-Label Exact Alias
Rename a burden while freezing identical declared challenge coverage.

Positive control against label essentialism.

### Attack 3 — Refinement Undercoverage
Old debt A refines to A1+A2; only A1 is covered.

Target:
```text
PARTIAL REFINEMENT COVERAGE != DEBT DISCHARGE
```

### Attack 4 — Full Refinement Preservation
A refines to A1+A2 and both are covered with ancestry intact.

Positive control:
```text
REFINEMENT CAN PRESERVE DECLARED DEBT SEMANTICS
```

### Attack 5 — Merge Debt Laundering
Debt-bearing and clear source burdens merge into one clear target burden.

### Attack 6 — Merge Provenance Preservation
Same merge, but source debt ancestry remains attached to target M.

Positive control.

### Attack 7 — Partial-Overlap Overclaim
OVERLAP is incorrectly treated as EXACT for debt retirement.

### Attack 8 — Unmapped Disappearance
A debt-bearing old burden vanishes from target ontology with no mapping or withdrawal.

### Attack 9 — Target-Novel Burden
Target ontology introduces N with no source predecessor.

Target:
```text
NOVEL TARGET BURDEN != SOURCE DEBT
```

Novel burden creates new constitutional load; it is not retroactively inherited debt unless an explicit rule says so.

### Attack 10 — Same Counts, Different Ontology
Two versions have equal burden counts and obligation counts but incompatible mappings.

Target:
```text
COUNT STABILITY != ONTOLOGY STABILITY
```

### Attack 11 — Refinement/Merge Cycle
A->B1+B2->C->A-like label cycle cannot establish identity merely by returning to the original name.

### Attack 12 — Noncommuting Revision Diamond
Direct and composed translation disagree.

### Attack 13 — Conflict by Translation
Old mandatory obligation translates into a target burden that the target constitution explicitly withdraws or forbids.

### Attack 14 — Arbitration by Recency
Newest ontology wins automatically.

Target:
```text
NEWER != EPISTEMICALLY SUPERIOR
```

### Attack 15 — Arbitration by Source Prestige
More external/prestigious source wins automatically.

Target:
```text
PROVENANCE STATUS != CONFLICT WINNER
```

### Attack 16 — Conflict Scalarization
Several localized obligation conflicts are collapsed to one scalar severity without declared weights.

### Attack 17 — Drift by Silent Definition Change
Version number changes and burden definitions drift without an explicit BORR.

Target:
```text
VERSION SUCCESSION != TRANSPORT RECEIPT
```

### Attack 18 — Debt Double Counting after Refinement
One old debt refines into two target burdens and is counted as two independent historical debts.

Target:
```text
REFINEMENT CARDINALITY != HISTORICAL DEBT MULTIPLICITY
```

### Attack 19 — Debt Collapse after Merge
Two independently originated debts merge into one target burden and are counted as one debt without retaining ancestry.

### Attack 20 — Cross-Constitution Total-Order Overclaim
Two constitutions are mapped only on a subset of burden coordinates but one is ranked globally better.

### Attack 21 — Mapping-Witness Endogeneity
The same revision process that proposes an EXACT map also supplies its only identity witness.

Allowed but marked; it earns no independence by self-certification.

### Attack 22 — Unknown Future Ontology
A passing BORR/CCE is used to infer that all future ontology revisions will be transportable.

Target:
```text
CURRENT TRANSPORTABILITY != REVISION CLOSURE
```

## Positive candidate principles

### Principle A — Burden Identity Is Witnessed, Not Label-Derived

Labels are neither necessary nor sufficient for cross-version identity.

### Principle B — Transport Is Typed and Loss-Aware

EXACT, REFINE, MERGE, OVERLAP, DISJOINT and UNMAPPED must remain distinct.

### Principle C — Refinement and Merge Can Preserve Governance Conditionally

Ontology change is not automatically destructive. Full refinement coverage and provenance-preserving merges can support local debt continuity.

### Principle D — Debt Ancestry Survives Representation Change

Historical debt cannot be multiplied or erased solely by split/merge cardinality.

### Principle E — Comparability Is Partial

Cross-constitution comparison is authorized only over the mapped burden domain.

### Principle F — Conflict Localization Precedes Arbitration

The checker should expose where obligations conflict before any higher-order rule selects a response.

### Principle G — Direct/Composed Disagreement Reopens Authority

A noncommuting revision diamond is a reopening event, not proof that the direct path is infallible.

### Principle H — No Ontology-Revision Closure

A passing BORR cannot prove that future burden ontologies are complete or losslessly translatable.
