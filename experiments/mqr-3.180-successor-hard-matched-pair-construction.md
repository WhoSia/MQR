## 1. Candidate family A — defeat-route noncommonness
Proposed pair:
- A has two apparently corroborating challenge routes with materially distinct dominant failure ancestry.
- B has two apparently corroborating challenge routes that collapse to a common upstream failure.

Desired MQR divergence:
- A retains stronger reopenability/defeat capacity.
- B receives reduced authority because apparent multiplicity is common-mode.

### Reduction attack
This axis is not successor-hard.

Mature work already treats:
- evidence independence and dependence;
- common-cause structure;
- independent vs self-reported evidence;
- defeaters and assurance confidence;
- source-lineage/provenance-based dependence.

Therefore an ordinary assurance/provenance/evidence-independence representation can distinguish A and B without importing a specifically MQR state.

**VERDICT A: KILLED / G4-C FAIL ON NONCOMMONNESS AXIS.**

## 2. Candidate family B — original route vs substitute route
Proposed pair:
- A preserves the original challenge route after transformation.
- B loses that route but introduces a new substitute route with similar current extensional coverage.

Desired MQR divergence:
- substitute capability is not identical to preservation;
- route ancestry and replacement status could affect successor burden/reopenability.

### Reduction attack
Current assurance-case research supports:
- evolving assurance cases;
- claim-evidence traceability;
- change-impact analysis;
- explicit defeaters;
- reusable defeater records across product/system evolution.

Thus original-vs-replacement evidence/defeater status can be represented within mature assurance evolution machinery.

No matched pair was found for which ordinary assurance evolution must classify A/B identically while MQR separates them.

**VERDICT B: KILLED-NARROW / NO SUCCESSOR-HARD PAIR.**

## 3. Candidate family C — replay competence/environment/cost
Proposed pair:
- A and B expose the same apparent challenge interface and return the same current test outcomes.
- A is independently replayable under preserved dependencies/environment.
- B is only nominally replayable because required environment/competence/infrastructure is unavailable or prohibitively reconstructive.

Desired MQR divergence:
- reachable challenge route differs despite extensional interface equality.

### Reduction attack
Scientific-workflow reproducibility research already treats:
- preservation of execution environments;
- dependency capture;
- workflow decay;
- infrastructure-aware provenance;
- reproducibility packages/capsules;
- replay/re-execution feasibility.

Therefore this axis is not distinct merely because replay feasibility changes authority.

**VERDICT C: KILLED / REPRODUCIBILITY PRIOR ART ABSORBS THE AXIS.**

## 4. Candidate family D — future-defeat reserve
Proposed pair:
- A and B are sufficient for the present claim and current verifier.
- A retains lower-level/raw/provenance material enabling later reanalysis under unforeseen challenge classes.
- B retains only terminal derivatives.

Desired MQR divergence:
- present equality but different future defeat topology.

### Reduction attack
Archival/reproducibility literature already explicitly motivates:
- preserving raw data for future reanalysis;
- preserving executable analyses for future reinterpretation/recasting;
- linking data, software, workflows and explanations;
- preservation decisions indexed to future reuse and recreation cost.

Hence “presently equivalent but future-reanalysis-divergent” is not by itself MQR-distinct.

**VERDICT D: KILLED / FUTURE-REUSE PRIOR ART ABSORBS THE AXIS.**
