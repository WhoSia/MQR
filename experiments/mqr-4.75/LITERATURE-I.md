# MQR-4.75 — Literature Collision I

Status: **POST-PRESEAL / MODEL-CRITIC-DEPENDENCE-BASELINE-ABSORBED / COMMON-MODE-ROUTE-RESIDUE-LIVE**

## 1. Posterior predictive checking absorbs generic model-criticism novelty

Gelman, Meng & Stern (1996) and Gelman et al. (2020) establish posterior predictive model checking and broader Bayesian workflow as iterative model criticism.

Key pressure:
- replicated data are generated using the fitted model;
- discrepancies are useful for locating model inadequacy;
- model checking is embedded in an iterative workflow of model building and improvement;
- a model-conditioned diagnostic is not thereby an external truth oracle.

Therefore MQR-4.75 claims no novelty for:
- posterior predictive checks;
- residual/discrepancy diagnostics;
- iterative model criticism;
- using model-generated replications to reveal misfit.

Residual question:
when does target-model dependence create an authority-relevant common mode, and when is it merely benign construction dependence?

## 2. Model discrepancy absorbs generic mismatch decomposition

Brynjarsdottir & O'Hagan (2014) emphasize that explicit model discrepancy can be crucial when learning physical parameters from imperfect models.

MQR consequence:
a discrepancy term can expose a mismatch while remaining model-structured.
No inference from "discrepancy exists" to "independent refutation" is licensed without a route/provenance receipt.

## 3. Many-analyst variation kills algorithm-diversity laundering

Botvinik-Nezer et al. (2020) and Breznau et al. (2022) show that different analysis teams can produce materially different results from the same or similar inferential task.

MQR gets no novelty for:
- analyst plurality;
- pipeline diversity;
- multiverse-style variation;
- disagreement among analyses.

Residual:
multiple pipelines are not automatically independent challenge generators.
Shared data, preprocessing, measurement representation, target assumptions or inferential grammar may create authority-relevant common modes.

At the same time, shared data alone is not sufficient to prove dependence.

## 4. Lakatos absorbs counterexample-driven mathematical revision

Lakatos's *Proofs and Refutations* already gives:
- global/local counterexamples;
- hidden lemmas;
- proof-generated concepts;
- monster-barring / concept revision;
- changing theorem content through criticism.

MQR-4.75 therefore claims no novelty for the idea that mathematical criticism and counterexamples reshape concepts or theorem domains.

Residual:
a bounded countermodel search procedure does not earn closure merely because it finds no witness, and formally different search algorithms may still share the same representational exclusion.

## 5. CEGAR / automated search absorbs iterative counterexample generation

Counterexample-guided abstraction refinement and automated model checking already provide iterative search/refinement loops in which discovered counterexamples drive model refinement.

MQR claims no invention of:
- counterexample generation;
- abstraction refinement;
- bounded model checking;
- automated critic loops.

The live authority issue is whether the search grammar or abstraction silently excludes the very counterexample family whose absence is being inferred.

This is route-relative and typed.
