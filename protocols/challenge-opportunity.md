# Challenge-Opportunity Allocation Protocol

Canonical stage: **MQR-3.139**

## Core laws

- `EQUAL STANDING != EQUAL ALLOCATION`
- `EXPECTED INFORMATION GAIN != EXPECTED AUTHORITY VALUE`
- `PROTECTED EXPLORATION != GUARANTEED FULL-SCALE EXECUTION`
- `CURRENT CHEAPNESS != INTRINSIC EPISTEMIC EFFICIENCY`
- `TRACK RECORD != ALLOCATION-INDEPENDENT MERIT`
- `ALLOCATED ADVANTAGE != INDEPENDENT AUTHORITY GAIN`
- `EXPENSIVE BECAUSE NEGLECTED != UNPROMISING BECAUSE EXPENSIVE`
- `PATH DEPENDENCE != ERROR`
- `UNTRACED PATH DEPENDENCE => AUTHORITY CEILING`
- `BROAD AUTHORITY + ZERO LIVE EXTERIOR OPPORTUNITY => REALLOCATION OR AUTHORITY CEILING`

## Dynamic Challenge Opportunity Profile

For each admitted challenge track:

`COP_t(q) = <D_t,N_t,C_t,K_t,R_t,V_t,S_t>`

and explicitly allow the profile to depend on allocation history.

- `D` — prospective discriminatory bite
- `N` — noncommonness of the failure route
- `C` — direct resource cost
- `K` — contamination / irreversibility cost
- `R` — certification-reserve consumption
- `V` — verifiability / auditability
- `S` — staging potential

Do not collapse COP into a universal scalar score.

## Opportunity-Allocation Feedback

Audit the loop:

`ALLOCATION -> TOOLS/SKILL/DATA/STATUS -> LOWER COST + HIGHER LEGIBILITY -> HIGHER APPARENT VALUE -> MORE ALLOCATION`

This loop can represent legitimate learning. It becomes authority-relevant when allocation-produced advantage is reported as if it were fully world-produced advantage.

## Cost ancestry

For load-bearing cost comparisons track where relevant:

- inherited infrastructure
- prior grants/investments
- shared datasets and labels
- accumulated operator expertise
- benchmark/standards compatibility
- facility/platform access
- fixed costs already paid
- capability decay caused by prior nonallocation

## Allocation-Induced Legibility

Operational legibility is useful, but:

`LEGIBLE NOW != MORE WORLD-REAL BY ITSELF`

A route may be easier to measure, review, benchmark or publish because previous allocation standardized its ontology.

## Counterfactual Allocation Replay

Ask:

> Would the route still look decisively cheaper, more legible or more productive if the compared alternative had received a plausibly comparable staged opportunity to build its minimal testing capability?

Possible states:

- `PATH-ROBUST`
- `PATH-SENSITIVE`
- `PATH-UNRESOLVED`

Path sensitivity does not mandate reverse funding; it caps claims that the observed ranking is allocation-independent scientific authority.

## Option-Preserving Allocation

Default when staging is scientifically valid:

`REGISTER -> PILOT -> DISCRIMINATE -> ESCALATE -> REPLICATE/CERTIFY`

A protected challenge receives a real route to world contact, not automatic maximal resources. Pilot-guided escalation does not make pilot and full execution two independent confirmations.

## Authority-Preserving Exploration Floor

No fixed exploration quota is constitutionalized. Instead:

> If a broad authority-bearing claim remains live while every materially noncommon admissible challenge has opportunity approaching zero, either restore some exterior challenge opportunity or contract the claim's authority/scope.

## Minimal Counter-Path Preservation

When broad authority depends on the practical absence of rivals, avoid letting every noncommon rival capability disappear solely because it initially lost the allocation race.

Possible realizers include preserving minimal datasets, protocols, interfaces, translation schemas, pilot capability, code environments, samples, or access receipts. No universal preservation quota is required.

## Capability atrophy

Audit:

`LOW ALLOCATION -> CAPABILITY DECAY -> HIGHER FUTURE COST -> LOWER ALLOCATION`

Absence of current applicants, tools or facilities is not automatically absence of a live scientific alternative.

## Path-Adjusted Marginal Authority Return

For a candidate next allocation ask both:

1. What new authority-bearing distinction can the next unit of resource expose?
2. How much of its apparent return is due to world-confirmed learning versus historically accumulated route-specific capacity?

No universal scalar decomposition is required.

## Challenge-Opportunity Ledger

Record where load-bearing:

- CAR/admission state
- dynamic COP dimensions
- ancestry / evidence family
- staging path
- direct and epistemic cost
- prior allocations and receipts
- infrastructure/skill/data accumulation
- cost ancestry
- allocation-induced legibility
- capability atrophy
- current-vs-start-up cost distinction
- track-record role
- counterfactual allocation replay result
- path-adjusted marginal authority return
- escalation / stop condition
- deferral reason
- reopening trigger

## Failure witnesses

- Incumbent Allocation Capture
- Fringe Resource Drain
- Opportunity-Allocation Feedback capture
- Matthew-Effect Lock-In
- Endogenous-Efficiency Laundering
- Capability Atrophy
- Selection starvation
- Opportunity-diversity collapse
- Pseudo-precision allocation
- Certification-reserve burn

## No historical reset

MQR does not require equal maturity or equal historical funding across routes. Genuine learning-by-doing and world-mediated success may rationally attract further resources.

The invariant is narrower: **do not treat historically produced opportunity gradients as if they were entirely world-produced gradients.**
